# 智能油库日报机器人

每日自动从数据库读取设备库存与同步状态，生成格式化 Excel 报表并推送至企业微信群。

---

## 功能概述

- 从 MySQL 数据库一次查询获取所有设备信息（库存百分比、在线状态、安装信息等）
- 根据 `modify_time` 距今时长及设备 `status` 字段，判断五级网络状态（在线 / 短期预警 / 长期离线 / 从未激活 / 停用）
- 生成微软雅黑字体、交替行底色、库存红绿灯、网络状态高亮的 Excel 报表；颜色采用静态格式写入，**在企业微信内置阅读器中直接可见**，无需第三方 Office 软件
- 「网络同步」列表头含悬停批注，说明各状态值含义，无需对照外部文档
- 报表支持 **A4 打印排版**：自动缩放至单页宽、页脚显示页码（第 X 页 / 共 N 页）、外框粗线/内框细线、冻结首行跨页重复、显式声明打印区域确保末列不截断
- `安装地点` 自动去除省份/自治区/直辖市重复前缀（如"广东省东莞市塘厦镇"→"东莞市塘厦镇"，"重庆市重庆市长寿区"→"重庆市长寿区"），节省列宽
- 通过企业微信 Webhook 将报表文件推送到指定群
- 支持**飞书文档**（API）/ **腾讯文档**（自动转换）/ **本地 Excel** 三渠道加载设备配置
- 支持"**未录入系统设备**"补录：设备已交付但未入库时，可在配置表中手动补录，自动追加到报表末尾
- 支持**飞书告警推送**：程序停止或出现非致命异常时，主动推送告警消息至指定飞书机器人
- 在线配置加载成功后，自动与本地配置对比设备数量，差异 ≥ 5 台时推送告警
- 每日 08:00 定时自动执行

## 设备配置文件格式

在线表格或本地 `device_config.xlsx` 须包含以下四个 Sheet：

### Sheet：设备配置

| 设备编号 | 客户名称 | 桶数 | 设备归属 |
|----------|----------|------|----------|
| TW001    | 中润     | 2    | 中润     |
| TW002    | 某客户A  | 1    | 客户A    |

> - `客户名称` 列仅供运维人员阅读，**代码不使用此列**，可留空。
> - **设备编号不可为空**；为空的行将跳过，并触发飞书告警。
> - **桶数、设备归属对非补录设备不可为空**；为空时触发飞书告警（补录设备豁免）。
> - 此 Sheet 为**非排除设备总表**，应包含**正常设备 + 计量设备 + 补录设备**，**无需包含排除设备**。
>   程序每次运行时自动核对：`设备配置总数 = 非排除数据库设备数 + 补录不在DB的设备数`，不符时飞书告警，并逐行列出差异设备编号。
> - 非补录设备若在数据库中无匹配记录，将触发飞书告警提示编号可能有误。

### Sheet：排除客户设置

| 排除客户名称           | 排除客户ID | 排除设备编码（...）               | 备注                              |
|------------------------|------------|-----------------------------------|-----------------------------------|
| 中润                   | 100046     |                                   | 测试客户，整体排除                |
| 贰壹陆                 | 100049     |                                   | 测试客户，整体排除                |
| 浙江杰威               | 100066     | MO24032700700019                  | 已替换旧设备                      |
| 浙江联众汽车零部件有限公司 | 100079  | TW24011700700032,TW24011700700033 | 已替换旧设备（多台用英文逗号分隔）|

> - `排除客户名称`：仅供运维人员阅读，**代码不使用此列**。
> - `排除客户ID`：**必填**，使用数据库 `customer_id`，避免同名客户误排除；为空或重复时触发飞书告警。
> - `排除设备编码`：**为空** → 排除该客户所有设备；**非空** → 只排除指定编号（英文逗号分隔），其余设备正常显示。
> - 若配置的客户ID或设备编码在数据库中无匹配，程序会在日志中记录并推送飞书告警。

### Sheet：计量客户设置

| 计量客户名称               | 计量客户ID |
|----------------------------|------------|
| 浙江荣发动力股份有限公司   | 100058     |
| 台州永裕工业有限公司       | 100070     |

> - **计量客户ID 必填**，为空或重复时触发飞书告警。
> - 若配置的客户ID无法匹配到报表数据，程序区分两种情形分别告警：
>   - **与排除规则冲突**：该客户ID同时出现在排除客户设置中且被整体排除 → 告警「配置冲突，请检查排除规则」
>   - **数据库无记录**：该客户ID在数据库中真正无设备 → 告警「请确认ID是否正确」
> - 配置后，报表将自动新增"**计量客户单列**" Sheet，格式与主表一致，序号独立编排。

### Sheet：未录入系统设备

> 设备硬件已交付给客户、但尚未录入管理系统（数据库无记录）时使用。设备录入系统后，需删除对应行。

| 未录入系统设备客户名称(必填项) | 未录入系统设备编码(必填项) | 安装日期(可选项，格式示例：2026.03.13) | 安装地点(可选项) |
|-------------------------------|---------------------------|----------------------------------------|-----------------|
| 某客户                        | TW25010100300001          | 2026.01.15                             | 浙江杭州        |

> - **客户名称和设备编号均为必填**，为空或设备编号重复时跳过该行并触发飞书告警。
> - 补录设备将追加到报表主表末尾，`油品型号` 显示为"**设备待安装调试且未录入系统**"，`网络同步` 显示 **disabled**（灰色）。
> - 若补录设备编号已在数据库中存在，程序自动将其归为正常设备处理，并推送飞书告警提示维护人员从此 Sheet 中删除该记录。

## 运行方式

### 本地运行

```bash
python main.py
```

启动后每天 08:00 自动触发（若 08:00 后启动，次日 08:00 再触发）。

### 服务器部署（Linux）

```bash
# 上传文件
scp main.py requirements.txt deploy_linux.sh user@server:/tmp/

# 一键部署为 systemd 服务（开机自启、崩溃自动重启）
ssh user@server
cd /tmp && chmod +x deploy_linux.sh && sudo ./deploy_linux.sh

# 常用运维命令
systemctl status  daily-report-robot   # 查看状态
journalctl -u     daily-report-robot -f # 实时日志
systemctl restart daily-report-robot   # 重启
```

### 服务器部署（Windows）

```bat
# 以管理员身份运行（nssm.exe 已包含在项目目录中）
deploy_windows.bat
```

### 生产环境凭据注入（推荐）

避免密钥硬编码在代码中，通过环境变量注入。根据部署系统选择对应方式：

#### Linux（systemd 服务）

编辑 systemd 服务文件（`/etc/systemd/system/daily-report-robot.service`），在 `[Service]` 段添加：

```ini
Environment="DB_PASSWORD=your_password"
Environment="WEBHOOK_URL=https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=YOUR_KEY"
Environment="FEISHU_APP_ID=cli_xxx"
Environment="FEISHU_APP_SECRET=xxx"
Environment="FEISHU_ALERT_WEBHOOK=https://open.feishu.cn/open-apis/bot/v2/hook/xxx"
```

保存后执行以下命令使配置生效：

```bash
systemctl daemon-reload && systemctl restart daily-report-robot
```

#### Windows（NSSM 服务）

[deploy_windows.bat](deploy_windows.bat) 已内置凭据注入的注释模板（第 62–70 行）。部署前打开脚本，将对应注释行取消注释并填入真实值，然后重新运行脚本即可。

也可在部署完成后通过 NSSM GUI 手动配置：以管理员身份运行命令提示符，执行：

```bat
nssm.exe edit DailyReportRobot
```

在弹出窗口的 **Environment** 选项卡中填入各环境变量，保存后重启服务生效。

```bash
python -m bumpversion bump patch   # 补丁版本：1.1.3 → 1.1.4（Bug 修复）
python -m bumpversion bump minor   # 次版本：  1.1.3 → 1.2.0（新功能）
python -m bumpversion bump major   # 主版本：  1.1.3 → 2.0.0（破坏性变更）

# 2. 推送到远程仓库（仅此一步，commit 和 tag 已自动完成）
git push --follow-tags
```

**自动完成的内容：**
- ✅ 更新 [main.py](main.py) 中的 `__version__` 字段
- ✅ 创建 git commit，消息格式：`v{new_version} 版本升级`
- ✅ 打 git tag：`v{new_version}`
- ✅ 推送 commit 和 tag 到远程仓库

#### 选项 2：手动方式（备选方案）

```bash

# 编辑 main.py 第 20 行：__version__ = '1.1.4'

# 2. 提交代码

git commit -m "v1.1.4 版本升级"

# 3. 创建标签

# 4. 推送到远程（包含 commit 和 tag）
```

## 数据流程

```
MySQL 数据库
    │
    │  一次 SQL 查询（t_device / t_customer / t_oil_type / t_device_oil）
    │  SQL 层已过滤：del_status=1（未删除）、customer_id/customer_name 非空
    ▼
get_db_data()
    │  返回：device_code, customer_id, customer_name, avai_ratio,
    │        device_status, modify_time, oil_model, install_time, location
    ▼
process_data()
    ├─ 1. load_config()  ← 飞书API / 腾讯文档导出 / 本地 Excel 三路回退
    │       ├─ 设备配置：空编号告警、非补录设备桶数/归属为空告警
    │       ├─ 排除客户设置：客户ID空值/重复告警
    │       ├─ 计量客户设置：客户ID空值/重复告警
    │       └─ 未录入系统设备：必填项校验、设备编号重复告警
    ├─ 2. 过滤空客户名设备（SQL层已过滤，Python层双保险）
    │   2b. 设备配置 DB匹配校验（非补录设备编号不在DB则告警）
    │       + 总数核对（配置数 ≠ 非排除DB设备数+实际补录数则告警，逐行列出差异）
    ├─ 3. 按 exclusion_rules 过滤（基于 customer_id 精准匹配）
    │       + 排除规则DB匹配校验（未命中则告警）
    ├─ 4. 按安装时间升序排列
    ├─ 5. 补全桶数、设备归属字段
    ├─ 6. check_sync()  ← device_status + modify_time 判断五级网络状态
    ├─ 7. 数据清洗（空值填充）
    ├─ 8. 按 metered_ids 筛出计量客户子集 → df_metered
    │       + 计量客户ID 未命中校验：区分「被排除规则过滤」与「DB真正无记录」分别告警
    ├─ 9. 生成序号
    ├─ 10. 列重命名与筛选
    └─ 11. 追加补录设备（仅追加不在DB的编号；已入库则归为正常设备并告警提示清理）
    │
    ▼
generate_excel_with_format(df_final, filename, df_metered)
    ├── Sheet "安卓设备日统计表"  ← 全量设备（含计量客户）
    └── Sheet "计量客户单列"      ← 仅计量客户（df_metered 非空时写入）
    │
    ▼
send_to_robot()  ← 上传并推送至企业微信
```

## 网络在线状态判断逻辑

| 优先级 | 条件 | 状态值 | 报表颜色 |
|--------|------|--------|----------|
| 1 | `t_device.status == 1`（已停用），或补录设备（待安装调试） | `disabled` | 灰色 |
| 2 | `modify_time` 为空（从未上报数据） | `never_synced` | 紫色 |
| 3 | `modify_time` 距今 **> 72 小时** | `offline` | 红色 |
| 4 | `modify_time` 距今 **24 ~ 72 小时** | `offline_warn` | 橙色 |
| 5 | `modify_time` 距今 **≤ 24 小时** | `online` | 绿色 |

## Excel 报表说明

| Sheet 名称 | 内容 | 触发条件 |
|------------|------|----------|

### 验收项目及结果（v1.0.0，测试日期：2026-03-16）

> **后续 Bugfix 与功能增强：**
> - **v1.0.1**：修复补录设备「已入库」判断漏洞。原逻辑以排除后的报表编号集（`existing_codes`）判断补录设备是否入库，导致「在DB但被排除」的设备被误判为未入库，以 `disabled` 状态追加到报表末尾。修复后改用全量 `_db_codes` 判断，排除设备不会再被重复追加。

## 设计决策记录

### 配置来源：SQL 直查 vs API 调用

早期版本调用后端 REST API 获取数据，现改为直接 SQL 查询：

| 维度 | API 方案（旧） | SQL 方案（当前） |
|------|--------------|----------------|
| 架构复杂度 | 两步（DB + HTTP） | 一步（DB） |
| 可靠性 | 额外故障点（网络/服务宕机） | 更可靠 |
| 数据一致性 | 两次请求时间点不同 | 同一查询快照 |

### 在线配置表加载策略

| 平台 | 加载方式 | 原因 |
|------|----------|------|
| 飞书文档 | 飞书开放平台 API | 公开分享链接仅返回预览页，无法直接下载 |
| 腾讯文档 | 自动转换分享链接为 `/d/export/{id}?format=xlsx` | 导出接口公开可访问 |
| 金山文档/WPS | 用户手动获取直链 | 服务端返回人机验证页，无法自动下载 |
| 本地 Excel | 直接读取文件 | 在线均失败时的兜底方案 |

### 排除规则：从名称匹配升级为 ID 匹配

早期按客户名称字符串过滤，存在同名误排除和空格匹配失败问题。改为按 `customer_id` 精准匹配：

| 旧方案 | 当前方案 |
|--------|---------|
| 配置列：`排除客户`（名称字符串） | 配置列：`排除客户ID`（数据库 ID） |
| 同名客户会被误排除 | ID 唯一，不存在误排除 |
| 空格导致匹配静默失效 | ID 为数字，无空格问题 |

### 库存字段修正：avai_oil → avai_ratio

| 字段 | 含义 | 问题 |
|------|------|------|
| `avai_oil`（旧） | 剩余油量（升），如 609.40 | 列名显示`库存(%)`，阈值 5/30 对升数永远绿色 |
| `avai_ratio`（当前） | 剩余百分比（%），如 60.90 | 与阈值匹配，红黄绿配色正常生效 |

### 设备总数核对：全量DB → 非排除DB

早期预期总数包含排除设备，导致配置表未收录排除设备时持续误报。改为从预期中扣除排除设备：

| 旧公式 | 当前公式 |
|--------|---------|
| `预期 = 全量DB设备数 + 补录不在DB数` | `预期 = (全量DB − 排除DB) + 补录不在DB数` |
| 排除设备须录入配置表，否则告警 | 排除设备无需录入配置表 |

### 报表颜色：条件格式 → 静态格式

xlsxwriter `ws.conditional_format()` 生成的颜色规则存储为 XML 条件规则节点，企业微信内置 Office 阅读器不解析此类节点，导致所有颜色不可见。改为按行逐格调用 `ws.write(row, col, val, fmt)` 并将颜色嵌入格式对象（`workbook.add_format`），颜色直接存储在单元格 XML 中，所有阅读器均可显示：

| 维度 | 条件格式（旧） | 静态格式（当前） |
|------|--------------|----------------|
| 颜色可见性 | 仅桌面 Excel，微信不可见 | 所有阅读器均可见 |
| 格式对象数量 | 少（规则集中） | 多（每种组合一个），通过 `_fmt_cache` 字典去重 |
| xlsxwriter API | `ws.conditional_format()` | `ws.write()` + `workbook.add_format()` |
